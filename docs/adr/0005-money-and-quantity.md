# ADR-0005 · เงินใช้ numeric(12,2) · จำนวนเป็นจำนวนเต็มในหน่วยฐาน

- สถานะ: Accepted · 17 พ.ย. 2026

## บริบท

ระบบเทียบวงเงินที่ขอบ ฿5,000 พอดี (US-002 AC 2) และแปลงหน่วยแพ็ค/ลัง (US-004) ถ้าใช้ทศนิยมแบบ float จะเกิดเศษอย่าง 4999.999999 แล้วตัดสินผิด

## ตัดสินใจ

- **เงิน:** PostgreSQL `numeric(12,2)` · C# `decimal` · JSON number 2 ตำแหน่ง
  - VAT = ปัดครึ่งขึ้น (MidpointRounding.AwayFromZero) 2 ตำแหน่ง คำนวณจาก subtotal ทั้งใบ ไม่ใช่ต่อบรรทัด
  - เทียบวงเงินด้วย subtotal ก่อน VAT (US-002)
- **ต้นทุนต่อหน่วยฐาน:** `numeric(12,4)` เพราะหารจากราคาลังแล้วอาจมีเศษ
- **จำนวน:** `integer` เสมอ
  - PR เก็บทั้ง `qty` (หน่วยที่เลือก) และ `base_qty`
  - PO และใบรับของเก็บในหน่วยซื้อ · สต็อกเก็บในหน่วยฐาน
  - หน่วยทศนิยม (กก., ลิตร) อยู่นอกขอบเขต (US-004 out of scope)

## ผลที่ตามมา

- ✅ ขอบเขต 5,000.00 ทดสอบได้แม่นยำ
- ✅ ไม่มีปัญหาปัดเศษตอนแปลงหน่วย
- ⚠️ ถ้าวันหนึ่งขายของชั่งน้ำหนัก ต้องเพิ่มหน่วยย่อย (กรัม) เป็นหน่วยฐาน

## ทางเลือกที่ไม่เลือก

- **เก็บเงินเป็นสตางค์ (bigint):** แม่นยำเหมือนกัน แต่อ่านใน DB และ debug ยากกว่า
- **double / float:** ไม่ใช้กับเงินในทุกกรณี
