## Story

ในฐานะ **ฝ่ายจัดซื้อ** ฉันต้องการ **ให้ระบบรวมรายการจาก PR ที่อนุมัติแล้วของทุกสาขา และแยกเป็นร่าง PO ตามผู้ขายให้อัตโนมัติ** เพื่อให้ **ทำใบสั่งซื้อของทั้งสัปดาห์เสร็จภายใน 30 นาที และไม่สั่งของซ้ำข้ามสาขา**

## Acceptance Criteria

ข้อมูลตัวอย่าง: PR สาขา 1 ขอน้ำดื่ม 2 ลัง + มาม่า 5 ลัง · PR สาขา 3 ขอน้ำดื่ม 3 ลัง · น้ำดื่มซื้อจากผู้ขาย X · มาม่าซื้อจากผู้ขาย Y

### US-005a — รวม PR เป็นร่าง PO

1. **รวมเฉพาะ PR ที่อนุมัติแล้ว** — Given PR สถานะ Approved 2 ใบ และ Submitted 1 ใบ, When เปิดหน้า "รวมรายการสั่งซื้อ", Then เห็นเฉพาะรายการจาก PR ที่ Approved
2. **แยกตามผู้ขาย** — Given ข้อมูลตัวอย่าง, When กด "สร้างร่าง PO", Then ได้ร่าง PO 2 ใบ: ผู้ขาย X (น้ำดื่ม 5 ลัง) และผู้ขาย Y (มาม่า 5 ลัง) ทุกใบสถานะ Draft (BR-05)
3. **เห็นที่มาแต่ละสาขา** — Given ร่าง PO ผู้ขาย X, When กดดูบรรทัดน้ำดื่ม, Then เห็นแยก สาขา 1 = 2 ลัง, สาขา 3 = 3 ลัง (ใช้ตอนกระจายของและรับของ)
4. **PR เปลี่ยนสถานะ** — Given สร้างร่าง PO สำเร็จ, Then PR ที่ถูกรวมเปลี่ยนเป็น Converted และไม่ปรากฏในหน้ารวมรายการอีก
5. **สินค้าไม่มีผู้ขาย** — Given มีสินค้าที่ยังไม่ผูกผู้ขาย, Then แสดงในกลุ่ม "ยังไม่มีผู้ขาย" และไม่ถูกสร้างเป็น PO จนกว่าจะเลือกผู้ขาย

### US-005b — ตรวจก่อนส่งอนุมัติ

6. **สินค้ามีหลายผู้ขาย** — Given น้ำดื่มขายได้ทั้งผู้ขาย X และ Z, Then ระบบเลือกผู้ขายหลักที่ตั้งไว้ และฝ่ายจัดซื้อเปลี่ยนเป็น Z ได้ก่อนสร้างร่าง PO
7. **ยอดขั้นต่ำ** — Given ผู้ขาย Y มียอดขั้นต่ำ 5,000 บาท และร่าง PO รวม 3,200 บาท, Then แสดงป้ายเตือน "ต่ำกว่ายอดขั้นต่ำ 1,800 บาท" ยังส่งขออนุมัติได้
8. **แก้ร่างได้** — ฝ่ายจัดซื้อแก้จำนวนหรือราคาในร่าง PO ได้ก่อนส่งขออนุมัติ และระบบคำนวณยอดรวมใหม่
9. **สิทธิ์** — เฉพาะ role Purchasing และ Owner เข้าหน้านี้ได้ คนอื่นได้ 403

## Out of scope

- ส่ง PO และอนุมัติ PO (US-002 และ story ส่ง PDF)
- เลือกผู้ขายที่ถูกที่สุดอัตโนมัติ (ต้องมีประวัติราคา P-07)
- รวม PR ข้ามรอบสั่ง (ของแห้งวันจันทร์ vs ของสดจันทร์+พฤหัส)
